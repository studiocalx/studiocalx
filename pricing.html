公開・更新方式について

同じ目的でも、公開後に誰がどのように更新するかで適した仕組みは変わります。

↗

Git / Static Site

軽量で表示が速く、シンプルな構成に向いています。GitHub＋Cloudflare Pagesを利用すれば、小規模な静的サイトではレンタルサーバーの契約・月額費用を抑えられるのがメリットです。更新時は制作側での反映を基本とし、更新頻度が低いサイトや固定情報中心のサイトに適しています。

公開先の例：GitHub ＋ Cloudflare Pages
小規模な静的サイトなら、レンタルサーバー費用をかけずに公開できる場合があります。独自ドメイン等は別途費用です。
▤

WordPress / CMS

お知らせや記事などを、お客さま自身で更新したい場合に適しています。サーバー・保守・アップデートを含めた運用設計が必要です。

公開先の例：WordPress ＋ レンタルサーバー

料金に含まれる範囲・含まれない範囲

あとから認識の違いが生まれないよう、標準料金の考え方を明記しています。

原稿・写真素材

原則として、お客さまからご提供いただく想定です。文章の整理・リライトは範囲内で対応します。取材・原稿の新規執筆・撮影・有料素材購入は内容により別途お見積もりします。

ページ・機能

各プランに記載したページ数・機能が目安です。予約、決済、会員機能、複雑なフォーム、外部システム連携などは標準範囲に含みません。

デザイン修正

初回提案後の軽微な修正を2回程度まで想定しています。大幅な方向転換、構成変更、追加ページ・追加機能は別途お見積もりします。

ドメイン・サーバー

ドメイン取得・更新料、レンタルサーバー、CMSや有料テーマ・プラグイン等の利用料は制作費に含みません。原則としてお客さま名義での契約をおすすめします。

公開後の保守

公開後の継続的な更新・監視・バックアップ・障害対応は標準料金に含みません。必要な場合は内容と頻度を伺い、別途ご提案します。

見積もり・お支払い

正式な金額・納期・作業範囲は、ヒアリング後に書面またはメッセージで提示します。着手前に内容をご確認いただき、合意後に制作を開始します。
